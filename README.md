Планы на этот проект:

  2) Понять как работает Docker

Первым делом нужно было выбрать ОС. Мой взгляд пал на дебиан по этим причинам:
  1) Долгая тестировка пакетов = меньше шанс, что все отвалится
  2) Минималистичность = серверу незачем тратить ресурсы на граф оболочку и прочее

Думал также ставить арч, но отказался по причине "Rolling release".

После установки дебиана на второй пк, поставил статический ip адрес, установил и настроил SSH вход по ключу для простого подключения. Так же на arch сделал алиас "sshconnect" для подключения. Отключил доступ по SSH через пароль и логин, причина - нейронки говорили что это спасает от брутфорса со стороны ботов. Если честно - не знаю зачем это, если у меня сервер никак не открыт внешними портами наружу.
Далее я начал изучать что такое Docker. Как я пока ,что понял ,это просто изолированная среда для запуска всяких приложений. Уменьшает вероятность проблемы "на одном устройстве работает, а на другом нет". Отличается от виртаульной машины, тем что использует ядро системы. Внутри контейнера также находятся свои зависимости, которые не пересекаются с другими контейнерами.

Подключил репозитории Docker следующими командами:
```
curl -fsSL https://download.docker.com/linux/debian/gpg \
  | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/debian \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
```

Первым делом на сервере я настроил Jellyfin. Скачал образ контейнера, запустил его, открыл веб-интерфейс по адресу 192.168.1.50:8096, прошёл первоначальную настройку и создал двух пользователей: администратора и зрителя.
После этого загрузил сезон «Волчицы и пряностей» и теперь наслаждаюсь просмотром. Jellyfin доступен с любого устройства внутри локальной сети. Пока что без понятия хорошо это или плохо.
Интересно, что видео не загружались только в двух браузерах — Яндекс Браузере и LibreWolf. С LibreWolf всё более-менее понятно, но почему с этим не справился отечественный браузер — пока не разобрался.  

При дальнейших тестах заметил, что при запуске видео, процессор бешенно нагревается. Решил это тем что пробросил видеокарту в контйнер и настроил аппаратное ускорение в самом WebUI. Нагрузка распределилась между процессором и видеокартой, теперь процессор не разгревается до сотки.  

Далее установил qbitTorrentWebUI для простоты скачивания фильмов и сериалов сразу на сервер. Сделал это ради простоты процесса, чтобы не кидать вручную фильмы в папки. Настроил папку установки которая просмотривается джеллифином, но это вроде не должно работать нормально, потому что нужно каждый раз сканировать библы.

Ради чистоты эксперимента решил попробовать запустить нейронку на основном ПК. Ладно, я сдался на этом этапе, я понял что это не имеет смысла практически совсем. Я сначала думал открывать порты наружу и в роутере делать forwarding на сервер. Понял что это гиблая затея, легче это реализовать через Tailscale и WireGuard. Был также вариант через AWS гонять трафик, но нужно покупать домен, а я этого делать не хочу.

Со следущего шага думаю перейти на управление сервером через Ansible. Плюсы его можно раскрыть по полной настраивая несколько серверов одновременно. Я же его использую просто потому что хочу. Создал отдельную папку для всякого связаным с Ansible. Создал файл inventory.ini, прописал в нем ip, пользователя и приватный ключ для входа. Для пробы софта написал простенький плейбук, который обновляет установленные пакеты. Как я понял это просто имитация команды "sudo apt update && sudo apt upgrade".  
```
- name: Update Debian packages
  hosts: myhosts
  become: true

  tasks:
    - name: Update package lists and upgrade
      ansible.builtin.apt:
        update_cache: true
        upgrade: safe
```

Далее мне в голову пришла идея: "Заходить на IP адреса сервисов через ip:порт как-то тупо" и я решил посмотреть какие есть решения. Есть решение натсроить Nginx reverse proxy и записать там все сервисы. Но позже я нашел еще более взрослое решение - перенести все контейнеры внутрь кубера и там уже с помощью ингреса перенаправлять запросы в контейнеры. Да я прекрасно понимаю что кубер для моей машины это слишком изботочное решение и обычного docker-compose хватит более чем, но думаю лишним опыт лишним уж точно не будет. Так что я решил поставить K3s, как более легкую версию кубера.  
Буду использовать ранее изученый инструмент для установки k3s.  
Выполнил:
```
ansible-galaxy collection install git+https://github.com/k3s-io/k3s-ansible.git
ansible-playbook -i inventory.ini -K k3s.orchestration.site
```
С первого раза естественно не запустилось, пришлось подковырять файл inventory.ini добавив в него:
```
[k3s_cluster:children]
server
agent

[k3s_cluster:vars]
k3s_version=v1.37.1+k3s1
api_endpoint=192.168.1.50

[agent]
```
Далее уже все пошло как по маслу и Ansible успешно установил на сервер k3s.
